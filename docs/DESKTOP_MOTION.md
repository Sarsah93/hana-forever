# 동작·상호작용 명세와 제약

날짜별 변경은 [WORKLOG.md](WORKLOG.md)에, 구조는 [ARCHITECTURE.md](ARCHITECTURE.md)에 있다. 이 문서는 현재 동작의 규칙과 검증 항목을 모아 둔다.

## 물리

- 120Hz 고정 간격, 발 기준 물리 픽셀 좌표, 발이 있는 모니터의 배율로 몸체·속도 환산.
- 바닥은 각 모니터 작업 영역의 아랫변(작업 표시줄 윗선). 몸 폭의 일부라도 바닥 위에 있으면 지지된다.
- 몸의 네 모서리가 어느 모니터 작업 영역에라도 들어가면 이동 허용. 그렇지 않으면 그 자리에서 멈추고 돌아선다.
- **모니터 사이(브릿지)**: 세로 범위가 겹치며 2px 이내로 맞닿은 옆 모니터만 건널 수 있다(`bridgedNeighbour`). 그 바닥이 낮으면 걸어서 떨어져 착지한 뒤 걷기를 이어 가고, 높으면 높이에 관계없이 도약(`crossTo`: 0.25–0.9초 포물선, 옆 모니터 안쪽 몸 폭+20px에 착지)해 계속 걷는다. 화면 바깥 가장자리, 위아래로 쌓인 배치, 떨어진 배치는 벽이다.
- 창의 좌우 측면은 벽, 윗면은 착지 면, 아랫면은 점프 시 천장. 최대화 창은 배경으로 취급(모니터별).
- **보이는 면만 벽이다.** 창 목록은 Z순서(앞이 먼저)라, 앞 창이 한쪽 면 전체를 덮은 창은 보이는 부분으로 잘라 쓰고(`visibleRects`), 남은 면도 점 단위로 가려졌는지 본다(`occludedAt`). 최대화 창 뒤에서 옆 모니터로 삐져나온 브라우저는 그 보이는 모서리에만 기댄다. 클릭 통과 오버레이(`WS_EX_TRANSPARENT`)와 거의 투명한 레이어드 창은 애초에 세지 않는다.
- 점프는 접지 상태에서 한 번만: 120ms 준비 → 충격량 → 중력 → 착지 220ms 회복.
- 걷다가 떨어지거나 도약해 착지하면 남은 걷기 시간만큼 걷기를 재개한다. 화살표를 떼면 재개하지 않는다(`stopWalking`).

## 동작 전환

자세를 다섯 군(서기 · 앉기 · 엎드리기 · 웅크리기 · 공중)으로 나누고, 군이 바뀔 때는 개가 실제로 거치는 자세를 끼운다(`plan`).

- 정착 인트로가 있는 자세(웅크리기·되새김질: 서기→엎드리는 중, 엎드려 쉬기: 고개 내리기)를 떠날 때는 인트로를 **거꾸로**(원래의 60%, 최소 120ms) 재생해 일어나는 장면을 만든다. 이미 사이클에 들어 있는 프레임은 건너뛴다(`outroOf`).
- 엎드리기 계열 → 서기·걷기·두 발 서기·웅크리기: 앉기 0.4초를 거친다. 서기·웅크리기 → 엎드리기 계열: 앉기 0.35초를 거친다. 앉기↔다른 군, 같은 군 안은 바로 바뀐다.
- 점프·낙하·착지·드래그 낙하·집중 모드 이동은 즉시 바뀐다. 전환 중에는 자율 선택·시선 시작·요구 두 발 서기를 미룬다(`transitioning`).
- 렌더러는 클립이나 방향이 바뀌면 200ms(같은 클립의 좌우 반전은 120ms) 동안 이전 프레임을 `lighter` 합성으로 가중 합해 디졸브한다(가중치 합 1이라 중간에 흐릿해지지 않음). `smooth` 클립은 각 단계 끝 최대 160ms를 다음 프레임으로 녹인다.
- 크기: 머리 크기를 기준으로 맞춘다(정면 서기 머리 폭 ≈ 90px, 측면 옆얼굴 ≈ 72px). 걷기 .57, 앉기·턱 긁기 .48, 하품·웃기 .45가 이 기준으로 바뀐 값이다.

## 자율 행동

가중치(합 100): 걷기 30, 서 있기 9, 점프 4, 두 발 서기 5, **쉬기 40**, 털기 4, 턱 긁기 4, 되새김질 4(웅크려 있을 때만, 아니면 쉬기). 쉬기는 앉기 4·엎드리기 4·엎드려 쉬기 3·뒤돌아보기 2·웅크리기 2·하품 2 가중치로 고르고, 쉬는 중에는 60% 확률로 다음도 쉬기라 한동안 이어진다(같은 자세 연속은 피함). 휴식 자세 6–14초, 두 발 서기 2–4.5초, 서 있기·걷기 2.5–5.5초 유지. 원샷(털기·하품·긁기)은 끝나면 서 있기로, 되새김질은 끝나면 웅크린 채로 남는다. 측면 전용 동작과 하품의 방향은 여유 공간이 넓은 쪽(양쪽 다 넉넉하면 랜덤). 자유 행동 시뮬레이션 15분 중 휴식 30% 이상을 테스트로 보장한다.

## 요구와 알림

- 요구: 150–330초 간격으로 간식·장난감·쓰다듬기 중 하나(직전과 다른 것). 풍선 60초. 요구 중에는 정면 두 발 서기로 조르고, 원샷 도중이면 끝난 뒤 선다.
- 풍선 위치: 머리 옆, 벽·화면 가장자리까지의 여유가 넓은 쪽. 반대쪽이 1.4배 이상 넓어지면 옮긴다.
- 해소: 쓰다듬기(호버 또는 교감 버튼) → 웃기, 간식 주기 → 웅크리고 되새김질, 놀아주기 → 점프 후 털기. 기다리던 것이면 상태줄 문구가 달라진다.
- 알림: 설정한 점심·퇴근 시각의 분이 되면 벽시계 풍선 90초(바늘은 설정 시각). 날짜를 저장해 하루 한 번만. 집중 모드에서도 울린다(요구 풍선은 멈춤).

## 쓰다듬기

머리 영역(스프라이트 위쪽 45%, 두 발 서기는 30%, 앉기는 38%)에서 0.7초 안에 36px 이상 움직이고 방향이 한 번 이상 바뀌면 쓰다듬기. 서 있으면 여유 쪽을 향해 엎드리고, 이미 엎드려 있으면 그대로 둔다. 쓰다듬기가 **2초 이상** 이어져야 눈감고 웃는 얼굴(하품 시트)로 바뀌며, 그 전에 손을 떼면 엎드린 채로 남는다. 하품 시트는 lie-front와 같은 방향 그림이라 엎드린 방향대로 반전되어 좌우가 뒤집히지 않는다. 0.9초 동안 손이 멈추거나 머리를 벗어나면 끝나고 1.6초 뒤 엎드리기로 돌아온다. 교감 버튼의 쓰다듬기는 4초 동안 유지된다.

## 커서 바라보기

커서 좌표만 30Hz로 읽는다(어디에도 보내지 않음). 대기·엎드린 상태에서 커서가 머리 기준 520px 안에서 0.5초 이상 움직이면 초당 60% 확률로 옆으로 앉아 커서 쪽을 본다(좌우 28px 히스테리시스). 커서가 머리보다 60px 이상 위면 고개 든 프레임. 커서가 3초 멈추거나 6–14초가 지나면 대기로 돌아온다. 요구 중·쓰다듬는 중·집중 모드에서는 하지 않는다.

## 집중 모드

켜면 즉시 조용해진다(요구 풍선·시선·걷기·점프 없음, 앉기/엎드리기/하품 정도만). 몸에 24px 여백을 둔 상자가 어떤 창과도 겹치지 않는 바닥 위치를 24px 간격으로 찾아 가장 가까운 곳으로 옮겨 엎드린다. 없으면 창을 숨긴다. 0.5초마다 다시 확인하고, 빈 자리가 1.5초 이상 유지되면 돌아온다(창 표시는 포커스를 뺏지 않음). 끄면 빈 자리 중 랜덤 위치로 돌아온다. 최대화 창은 이 판정에서 예외 없이 장애물이다.

창이 숨겨진 동안 WebView2는 `requestAnimationFrame`을 멈추므로, 200ms 타이머가 프레임이 멈추면 대신 시뮬레이션을 진행한다 — 이것이 없으면 해제도 복귀도 감지되지 않는다. 숨김/표시는 둘 다 raw `ShowWindow`로 하여 tao의 가시성 플래그와 어긋나지 않게 한다. 트레이의 "작업 표시줄 위로 데려오기"는 집중 모드를 끄고 바로 부른다.

## 클릭 통과

전역 커서를 30Hz로 읽어 하나 창 안의 캔버스 알파(>12)를 확인한다. 하나 몸이나 풍선 위에 있을 때만 창이 마우스를 받고 나머지는 자동으로 통과한다. 드래그 중에는 바꾸지 않는다. 설정의 "클릭 통과"는 전체 통과 고정이며 트레이 메뉴로 되돌린다.

## 명시적 제약

- 최대화 창처럼 몸 전체가 들어갈 공간이 없는 창은 배경으로 취급한다(집중 모드에서는 장애물).
- 창 모서리의 둥근 형태는 사각형으로 근사한다. 몸도 발 기준 AABB다.
- 작업 표시줄 자동 숨김에서는 Windows가 보고하는 작업 영역 바닥을 따른다.
- 모니터 사이 이동은 옆으로 맞닿은 배치에서만 된다(바닥 높이·배율 차이는 상관없음). 위아래로 쌓였거나 떨어진 모니터 사이는 드래그로만 옮길 수 있다. 도약 중에는 창을 무시하고 착지 후 밀어낸다.
- 가려짐 판정은 앞 창이 한쪽 면 전체를 덮는 경우만 사각형으로 자르고, 모서리만 겹치면 점 판정에 의존한다.
- 동작 전환은 기존 프레임의 재배열·합성이다. 엎드림에서 실제로 일어나는 그림은 없다.
- 자동 실행은 켤 때 실행 중이던 exe 경로를 등록한다. 설치본에서 켜야 하고, 설치 위치를 옮기면 다시 켠다.
- 패널 위치는 하나 창과 같은 배율을 가정한다. 배율이 다른 모니터에 걸치면 몇 px 어긋날 수 있다.
- 서 있는 자세에서 쓰다듬으면 엎드린 뒤 웃는다(서 있는 웃는 얼굴 에셋 없음).
- 커서 바라보기는 앉은 자세(좌우·고개 들기)만 표현한다.

## 검증

- `npm test`: 물리 15 + 행동 23 = 38개(도약·브릿지·걷기 재개·실측 듀얼 모니터 6종·가려진 창·전환 안무·디졸브 위상 포함).
- `npm run build`: tsc와 세 페이지 번들(main·panel·guide). `cargo build` 통과.
- 실제 화면: 2026-09-10 `npm run tauri dev`로 렌더링·트레이·패널·클릭 통과 확인(WORKLOG 참조). 2차 수정분(디졸브·도약·기대기 진단·가이드·자동 실행·집중 모드 복귀)은 실화면 미확인.

Windows 수동 확인 목록: 밝은/어두운 바탕에서 사각형 흔적 없음 → 작업 표시줄 발 접지 → 모니터 경계 넘기(자율 걷기, 바닥 높이가 다른 배치) → 브라우저 양옆 기대기(콘솔의 `[hana] lean on` 창 확인) → 창 이동/최소화 → 점프 → 드래그 낙하 → 머리 쓰다듬기 → 요구 풍선 아이콘 후 교감 탭 → 점심 알림 → 집중 모드에서 창 최대화 시 숨김·해제 복귀·"데려오기" → 100/150/200% 배율 → 클릭 통과 후 트레이 복구 → 자동 실행 체크 후 재로그인 → 사용법 가이드 창.

## API 근거

- [Tauri WindowConfig](https://v2.tauri.app/reference/config/#windowconfig): 투명·그림자·숨김 시작 창.
- [Tauri Monitor.work_area](https://docs.rs/tauri/2/tauri/window/struct.Monitor.html): 모니터별 작업 영역.
- [Microsoft EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows), [DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute): 창 프레임·cloaked 필터·테두리 억제.
- [ShowWindow SW_SHOWNOACTIVATE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow): 집중 모드 복귀 시 포커스 유지.
