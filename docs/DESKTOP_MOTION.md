# 바닥·창 충돌과 동적 스프라이트 (2026-09-09)

## 이번 변경

기존 빌드 수정 브랜치 `claude/hana-forever-build-check-tjrpgs`의 39e7121에서 이어 작업했다. 원본 사진/영상과 기존 두 정지 PNG는 보존했다.

- `shadow: false`, 투명 WebView 배경, Windows 11 DWM 테두리 억제, CSS 그림자 제거. Tauri의 장식 없는 창에서 shadow=true가 만드는 흰 1px 사각형 테두리를 제거한다.
- Windows `GetMonitorInfoW.rcWork.bottom`을 발이 닿는 바닥으로 사용한다. 스크린샷의 빨간 선 좌표를 하드코딩하지 않는다.
- `EnumWindows` + DWM 프레임 경계를 250ms 간격으로 읽는다. 숨김/최소화/다른 가상 데스크톱/cloaked 창, 자기 프로세스, 바탕화면, 작업 표시줄, 도구 창은 제외한다. 창 제목·내용이나 화면 픽셀은 수집하지 않는다.
- 좌우 측면은 벽, 윗면은 착지 가능한 면, 아랫면은 점프 시 부딪히는 천장이다. 창 이동/크기 변경 시 겹침을 해소하고, 지지하던 창이 없어지면 중력으로 떨어진다.
- 120Hz 고정 물리 간격, 발 기준 물리 픽셀 좌표, DPI에 맞춘 몸체/속도, 절대 창 위치 전송과 IPC 병합을 사용한다.
- 대기, 좌우 걷기, 창에 앞발 기대기, 점프 준비/상승/하강/착지 스프라이트를 실제 프레임으로 렌더링한다.
- 걷다가 닿은 벽이 앞발 높이에 있으면 뒷발을 접지한 채 약 1.8초 기대고 돌아선다. 접촉이 없는 기대기 요청은 거절한다.
- 점프는 접지 상태에서 한 번만 발동한다. 120ms 준비 → 위로 충격량 → 중력 → 충돌로 착지 → 220ms 회복. CSS 점프 반복은 없다.

## 조작

| 조작 | 동작 |
| --- | --- |
| F2 / 하나 우클릭 / 트레이 메뉴 | 행동 패널 |
| ← / → | 누르고 있는 동안 걷기 |
| Space / 하나 더블클릭 | 제자리 점프 |
| 하나 드래그 후 놓기 | 위치 이동 후 낙하/접지 |
| 패널의 좌우 걷기 | 지속 걷기, 벽에 닿으면 기대고 돌아서기 |
| 스스로 돌아다니기 | 대기·걷기·가끔 점프 선택 |
| 트레이 → 작업 표시줄 위로 데려오기 | 바닥 빈자리 복귀 + 클릭 통과 해제 |

네이티브 앱에서는 패널을 닫고 시작한다. `npm run dev`의 브라우저 미리보기는 가상 브라우저 장애물과 40px 작업 표시줄을 그린다. 실제 데스크톱 처리는 `npm run tauri dev`에서 확인한다. F2/방향키/Space는 하나 창에 포커스가 있을 때만 동작하며 전역 키 감시는 하지 않는다.

## 아트 상태

`assets/sprites/motion-v2/hana-atlas.png`: 내장 이미지 생성 도구로 만든 RGBA 1254×1254 아틀라스, 16개 키포즈. 생성 시 2048×2048을 요청했지만 실제 반환 크기는 1254×1254이므로 실측 rect/발 앵커를 사용한다. 원본 이미지 생성 결과의 알파 채널을 유지했다.

| 행 | 포즈 | 재생 |
| --- | --- | --- |
| 1 | 정면 네발 대기·호흡·눈깜빡임 4개 | 프레임별 지속 시간 |
| 2 | 오른쪽 측면 걷기 4개 | 8fps, 왼쪽은 반전 |
| 3 | 앞발 들기→뻗기→창 기대기 4개 | 진입 후 마지막 2프레임 호흡 |
| 4 | 웅크림·상승·공중·착지 4개 | 물리 상태에 따른 선택 |

이번 것은 동작 연결을 검수할 1차 키포즈 팩이다. 고프레임 최종 애니메이션이나 실제 영상에서 추출한 모든 동작이 아니다. `빠르게`는 걷기 프레임을 12fps로 재생하며 독립적인 달리기 스프라이트는 아직 없다. 기존 정면 `stand-up` 정지 포즈도 계속 사용할 수 있다. 기존 행동 ID 13종은 보존했고, 나머지 앉기/잠자기/긁기 등의 아트는 후속 작업이다.

얼굴·귀·털색은 기존 스프라이트와 실제 사진을 참조했다. 다음 아트 단계는 걷기 8–16프레임 보강, 기대기 진입/복귀 중간 포즈, 독립 달리기, 원본 영상 기반 두발서기 표정 확장이다.

## 명시적 제약

- 최대화/전체 화면 창으로 몸 전체가 들어갈 공간이 없는 경우 해당 창을 배경으로 취급해 작업 표시줄 위에서 돌아다닌다. 일반 크기의 브라우저 창에는 사방 충돌을 적용한다. 화면 전체를 고체 장애물로 두면서 동시에 하나를 화면 안에 보이게 할 수 없는 경우를 위한 처리다.
- 여러 창이 화면을 촘촘히 가득 채워 유효한 탈출 후보가 전혀 없는 경우의 배치는 추가 개선 대상이다. 완전히 가린 창은 제외하지만 부분 가림 경계를 다각형으로 분할하지는 않는다.
- 작업 표시줄 자동 숨김에서는 Windows가 보고하는 작업 영역 바닥을 따른다. 자동 숨김 막대를 강제로 표시하지 않는다.
- 현재 모니터 안에서 좌우로 움직인다. 드래그로 다른 모니터에 옮긴 뒤 새 작업 영역/DPI를 읽는다. 모니터 사이 자유 보행은 후속 단계다.
- 창 모서리의 둥근 형태는 사각형 충돌로 근사한다. 기본 몸체도 발 앵커 기준의 보수적인 AABB다.
- 투명 영역 클릭 자동 통과는 아직 없다. 기존 전체 클릭 통과 옵션과 트레이 복구를 제공한다.

## 검증

`npm test`: 바닥 좌우 이동, 1회 점프/회복, 양쪽 벽 기대기, 벽 제거, 창 위 이탈·낙하, 지지창 제거, 빠른 낙하, 천장 충돌, 겹침 해소, 음수 모니터 좌표/150% DPI, 화면 경계, 최대화 예외, 프레임 선택을 검사한다.

`npm run build`: TypeScript와 프로덕션 번들을 검증한다. 실제 Windows 네이티브 빌드 결과와 시각 확인은 작업 완료 시 별도로 기록한다. 자동 물리 테스트가 Windows 11 실제 화면에서의 테두리/DPI 검증을 대신하지 않는다.

Windows 수동 확인: 밝은/어두운 바탕에서 사각형 흔적 없음 → 작업 표시줄 발 접지 → 양방향 걷기 → 일반 브라우저 양옆에 기대기 → 창 이동/최소화 → 제자리 점프 1회 후 착지 → 드래그 후 낙하 → 100/150/200% 배율 → 클릭 통과 후 트레이 복구.

## API 근거

- [Tauri WindowConfig](https://v2.tauri.app/reference/config/#windowconfig): shadow와 투명 배경 설정. 장식 없는 Windows 창에서 shadow=true는 흰 1px 테두리를 만들 수 있다.
- [Microsoft MONITORINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-monitorinfo): rcWork 작업 영역.
- [Microsoft EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows): 최상위 창 열거.
- [Microsoft DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute): 화면 프레임, cloaked 필터, 테두리 억제.
